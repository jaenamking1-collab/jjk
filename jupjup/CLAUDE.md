# 줍줍 링크 메모 (크롬 확장)

Shift+클릭·Shift+드래그로 주운 링크를 메모 창(화면 1/3 popup) 칸에 모은다. 빌드 없음.

- `content.js` 페이지에서 줍기·복사 / `background.js` 보관함(pending)·창 열기 / `board.*` 메모 화면.
- 저장은 `chrome.storage.local`(`board`, `pending`, `bounds`)이 기본이다. 설정에서 폴더를 고르면 `store.js` 가 `jupjup-links.json` 으로도 쓴다(폴더 핸들은 IndexedDB). 창을 열 때 `savedAt` 이 더 새 파일을 쓴다. 기본 상태에서는 **확장을 제거하면 지워진다.** 권한이 풀리면 톱니에 빨간 점이 뜬다.
- 판은 몇 개든 저장한다. `shown` 은 화면 자리(최대 4)에 놓인 판 번호, `layout` 은 보이는 자리 수다. 줄여도 지우지 않고, 숨은 판은 목록에서 꺼낸다.
- 시험: 브랜드 크롬은 `--load-extension` 이 안 먹어 Playwright 크로미움으로 돌린다. Claude 앱이 AppData 쓰기를 돌려서 크로미움을 AppData 밖으로 복사해야 실행된다. `--window-size` 를 주면 팝업 크기가 덮어써져 1/3 검사가 틀린다. 학교 PC 는 `PLAYWRIGHT_BROWSERS_PATH=C:\Users\azsxd\pw-browsers` 에 받아 두었고, 헤드리스는 `channel='chromium'` 이어야 확장이 켜지며 팝업 창이 안 열려 `board.html` 을 직접 연다. 사진·줍기 시험은 `python jupjup/test_photos.py`(43항목).
- 실제 사이트 시험은 Aside 로 한다: `chrome://extensions` 에서 개발자 모드·'압축해제 로드'를 누르고 폴더 창에 경로를 넣으면 진짜 설치 경로로 돈다. 네이버 뉴스처럼 복잡한 곳을 꼭 본다.
- 설치: `install.bat` 더블클릭. jjk 가 있는 PC 는 git pull, 없는 PC(전산실 등)는 GitHub Pages(`jaenamking1-collab.github.io/jjk/jupjup/`)에서 `%USERPROFILE%\jupjup` 로 받고 매일 12시 예약 작업(`jupjup-update`)으로 다시 받는다. 학교망은 raw.githubusercontent.com 이 막혀 Pages 를 쓴다. 새 파일을 만들면 bat 의 받을 파일 목록에도 넣는다. `install.bat` 은 CP949 로 저장한다(UTF-8+chcp 65001 이면 한글 줄이 끊겨 명령으로 실행됨). 크롬은 명령줄의 chrome:// 주소를 안 열어 주소를 복사해 붙여넣게 한다.
- 파일을 고치면 manifest 버전을 꼭 올린다. 켜져 있는 확장이 1분마다 폴더의 버전을 보고 스스로 다시 켠다(1.2.3부터). 집 PC 크롬은 Profile 14 가 아니라 Default 프로필에 설치돼 있다.
- 제목 우선순위(사용자 지정): 게시글 제목(링크 글자) → 글자가 없거나 잘렸을 때만 연결된 페이지 제목. 탭 이름·사이트 이름을 제목으로 쓰지 않는다. SNS 는 제목이 없으면 `@아이디`(주소에서, 인스타 게시물은 그 페이지에서).
- Shift+드래그는 칸(제목+사진) 단위다(사용자 지정 2026-11-03): 제목 가운데(`mainTitles`)나 큰 사진(150×120 이상) 가운데가 네모 안이면 그 칸을 줍고, 칸마다 링크와 사진을 둘 다 줍는다(제목 → `cardImage`, 사진 → `photoPost`). 작은 사진은 검색·뉴스 썸네일로 보고 링크만(실제 구글 검색 80×80 12장 제외 확인). 제목도 큰 사진도 없으면 60px 이상 사진을 줍는다. 구글 이미지 칸 링크는 `data-lpage` 로 맞춘다(`linkUrl`). 네이버 뉴스 썸네일은 110×75·95×65 등 전부 기준 미만(Aside 로 측정). 제목 글자는 화면에 안 보이는 글자(네이버 '새 창 열림', 0×0 clip)를 빼고 읽고, 크기·위치는 그 글자를 그리는 안쪽 칸으로 잰다(`textBox`) — 네이버 블로그 제목 링크는 13px 넓은 상자라 예전엔 빠지고 사진 링크의 '새 창 열림'이 잡혔다.
- 다른 글로 가는 링크가 없는 사진(상품·블로그 본문)은 지금 페이지 주소를 링크로 함께 줍는다(네이버 블로그는 틀 밖 주소). 단 링크 없이 눌러야 이동하는 작은 상품 칸(사진 폭 320 이하, 칸 폭이 사진의 2.2배 이하 — 네이버 '방금 본 상품')은 칸 속 숨은 http 주소, 없으면 상품명(글자 수 많은 줄)으로 `페이지#:~:text=상품명` 링크를 칸마다 만든다(`cardLink`). '방금 본 상품' 칸은 개인화라 Aside 에서 띄우지 못해 실제 구조는 미확인. Aside 시험: `aside repl` 은 파일을 못 읽으니 content.js 를 JSON 문자열로 스크립트에 넣어 `page.evaluate` 로 `eval` 하고 `chrome` 을 흉내 낸다. 사진은 클릭이든 드래그든 그 사진이 나온 게시글 링크도 같이 줍는다(`photoPost`: 감싼 링크 → 구글 이미지의 `data-lpage`(제목은 그 칸의 긴 줄) → SNS 글 묶음).
- 사진(2026-11-03 사용자 지정): 주운 사진도 링크처럼 대기하다가, 칸을 누르면 링크는 그 칸에·사진은 사진 칸(`photos: true`)에 동시에 들어간다(`paste` → `placePhotos`). 바로 넣지 않는다. 사진 칸은 사진만: 제목 칸 없이 "사진 n장", 사진 칸을 누르면 사진만 꺼내고(`take` 의 `kind`) 링크는 계속 들고 있으며, 링크 줄은 사진 칸에 끌어 놓을 수 없다. 사진에는 함께 주운 링크 주소(`post`)가 붙고, 그 링크를 지우면 사진도 지운다(`removeItems`). 1칸 보기면 2칸으로 바꾸고, 자리 남은 사진 칸 → 둘째 자리가 비었으면 그 칸 → 새 판 순이며, 사진 칸은 늘 둘째(오른쪽) 자리로 옮긴다(2026-11-09 사용자: 셋째에 두면 링크 판이 늘 때 밀려 사라짐, `photoSpace`). 머리줄 사진 버튼(`hidePhotos`)으로 사진 칸을 숨기면 2칸 보기는 링크 칸이 한 칸으로 넓어진다. 사진 칸은 4장씩 줄, 칸당 12장. 롤오버 크게·클릭 확대·x·내려받기·끌어 자리 바꾸기(밀린 사진은 살짝 들림).
- 사라진 링크는 `linkHealth`(background 가 6시간마다 60개, 설정에서 전체)에 두고 화면만 회색 줄을 긋는다. 404·410 또는 연결 실패 2번만 사라짐으로 본다. 로그인 페이지로 200 을 돌려주는 곳(인스타·카페 글 삭제 등)은 못 잡는다.
- 우클릭 '사진 다른 이름으로 저장 (줍줍)'(1.9.0, 2026-11-09): 따로 쓰던 사진 저장 확장을 합침. 크롬은 확장 메뉴를 기본 메뉴 아래에만 둬서 '이미지를 다른 이름으로 저장'보다 위로 못 올린다. 1.9.1 부터 옛 확장처럼 JPG·PNG·WebP 로 바꿔 저장도 한다(`saveImage`, 항목이 여럿이라 크롬이 '줍줍 링크 메모' 아래로 묶음). 못 받는 사진은 원본으로 저장. 1.11.1 부터 모든 사이트·모든 곳에서 페이지의 우클릭 차단(contextmenu·오른쪽 mousedown/up)을 window 캡처에서 끊는다(사용자 지정: 사진만 → 전부). 그래서 구글 문서·시트 같은 앱의 자체 우클릭 메뉴 대신 크롬 메뉴가 뜬다. 글자 선택·복사 막힘은 안 푼다. 파일 이름은 그 사진의 게시글 제목(`photoPost` 제목 → h1 → 탭 제목, 우클릭한 사진은 content 의 `rightImg`, background `photoName`)이고 같은 이름은 크롬 uniquify 로 `제목 (1)`·`(2)`(1.12.0, 2026-11-09 사용자). 원본 저장 확장자는 주소 → HEAD content-type → jpg.
- Shift+클릭 규칙(사용자 지정 2026-11-02): **게시글이면 게시글 링크, 사진·영상이면 그것.** 사진을 감싼 링크가 다른 곳으로 가면 게시글이고, 이 페이지나 사진 파일을 가리키면 사진이다(`goesElsewhere`). 본문 안의 링크 없는 사진은 사진이다. SNS(쓰레드·인스타·X·블루스카이) 피드는 사진이 `<a>` 밖이고 주소가 시간 표시에만 있어 `snsPost` 가 글 묶음을 올라가 찾고, 그 글 자체의 페이지에서는 사진을 줍는다. 지메일은 메일 줄.
- 게시글 링크를 고른 자리가 사진 위면 사진도 같이 줍는다(2026-11-03 사용자: 링크는 붙여넣고 사진은 동시에 다른 칸, `withPhoto`). 복사는 링크만. 스레드 사진은 클릭을 안 받아(pointer-events) 겹친 칸 안에서 그 자리를 덮는 `img` 를 찾는다. 인스타 CDN 사진 주소는 며칠 뒤 만료(`oe=`)되므로 사진 칸에 넣을 때 1280px JPEG 사본(`thumb`)을 저장하고 화면은 사본으로 그린다.
- 틀렸던 것: ① 줄 안 `<a>` 에 `draggable=false` 를 주면 줄 끌기가 막힌다 ② dragover 중 빈 칸 안내를 지우면 놓기가 끊긴다 ③ (뒤집힘) 사진+제목 카드에서 사진을 고르게 했더니 게시글을 못 찾아갔다 — 위 Shift+클릭 규칙이 정답이다 ⑤ 아이콘을 바꿔도 작업표시줄은 같은 주소의 옛 아이콘을 기억한다 — 메모 창 주소에 버전을 붙였으니 아이콘을 바꾸면 manifest 버전을 올린다 ⑦ 빈 주소를 `new URL('', 페이지)` 로 풀면 페이지 주소가 돼 구글 이미지의 `data:` 사진이 검색 페이지 주소로 저장됐다 — `httpUrl` 은 빈 값을 거르고 `data:image` 는 그대로 쓴다 ⑧ 헤드리스 시험에서 메모 창이 뒤에 있으면 CSS 전환이 멈춰 버튼이 안 보인다 — `bring_to_front` 뒤 확인 ⑥ 같은 주소 링크가 둘이면 글이 긴 쪽을 남겨 구글 첫 결과(따로 된 사이트 주소 줄)가 빠졌다 — 제목다운 큰 글자를 남긴다 ④ 창이 화면 맨 위부터 열려 브라우저 제목표시줄을 덮었다 — 페이지 높이부터 연다.
