# 노치 고양이 (notch-cat) 설계

> 2026-11-10 학교 PC에서 사용자와 정함. 구현은 Fable 세션이 맡는다.
> 위치: `jjk/notch-cat/` (공개 저장소 — 할 일·파일 목록 등 개인 데이터는 절대 저장소에 쓰지 않는다)

## 목차
1. 목적과 기준 · 2. 기술 · 3. 화면과 움직임 · 4. 기능 5개 · 5. 고양이 · 6. 생존 표시 · 7. 빌드·배포 · 8. 단계 · 9. 검증

## 1. 목적과 기준
- 윈도우 모니터 위쪽 가운데에 떠 있는 노치(다이내믹 아일랜드). 참고한 제품은 **Nusa**(rama2555/nusa, 스토어판 1.2.1)이다.
- **합격 기준은 "Nusa만큼 깔끔하고 부드럽다"이다.** 사용자가 완성할 때까지 Nusa를 켜 두니, 매 단계 나란히 띄워 비교한다.
- 넣지 않는 기능: 클립보드 기록(`Win+V`), 볼륨·밝기 창(윈도우 기본), CPU, 기도 시간, 물 마시기, 날씨, AI 대화.

## 2. 기술 — Nusa와 같은 방식
- 2026-11-10에 설치된 Nusa를 직접 확인했다: exe 하나 1.3MB, Rust(`rustc`·`cargo` 흔적), 불러오는 부품은 `d2d1`·`dcomp`·`d3d11`·`dxgi`뿐(WebView2·.NET 없음), 메모리 35MB, 음악은 GSMTC, 가사는 LRCLIB.
- 그래서: **Rust + `windows` 크레이트**, Direct2D(그리기) + DirectComposition(투명 합성) + DirectWrite(글자, 기본 글꼴 맑은 고딕).
- 창: 항상 위, 작업표시줄에 안 뜸, 투명 배경. 노치 모양 밖은 클릭이 아래 창으로 통과한다.
- 목표: 초당 60장, 평소 메모리 50MB 이하, 쉴 때 CPU 1% 아래.
- 움직임: 모든 크기·위치 변화는 **스프링**(감쇠 있는 용수철)으로 한다. 일정 시간 동안 일정 속도로 움직이는 방식은 쓰지 않는다. 모니터 주사율에 맞춰 그린다(DComp 커밋 + `DwmFlush` 또는 대기 타이머).

## 3. 화면과 움직임
- **닫힘**: 작은 알약. 왼쪽에 고양이, 오른쪽에 상태 한 줄(재생 중이면 곡명, 아니면 시세 한 종목). 알림이 오면 잠깐 넓어졌다 돌아온다.
- **펼침**: 마우스를 올리면 스프링으로 커진다. 쪽은 음악 / 선반 / 할 일 / 시세 4개이고, 휠·←→ 키·위쪽 점으로 넘긴다. 마우스가 나가면 접힌다.
- 전체 화면 앱(게임·영상·슬라이드)이 앞에 있으면 숨는다(설정으로 끌 수 있음). 넓은 모니터에서는 크기를 키운다.
- 트레이 아이콘: 설정, 끝내기, 버전, 새 버전 알림.

## 4. 기능 5개
| 기능 | 내용 | 데이터 |
|---|---|---|
| 음악 + 가사 | GSMTC로 곡·앨범 그림·재생 위치. 재생/멈춤/넘기기/탐색. 가사는 LRCLIB(`/api/get`, 없으면 `/api/search`). 줄마다 강조하고, 줄을 누르면 그 위치로 이동. 가사 알약은 줄 길이에 맞춰 늘고 준다. | 가사 캐시: `%APPDATA%\notch-cat\lyrics\` |
| 파일 선반 | 노치에 끌어다 놓기(OLE 드롭), 다시 끌어내기(OLE 드래그). 여러 개 선택. 끌어내다 노치로 되돌리면 그대로 남는다. 파일은 복사하지 않고 경로만 기억한다. 원본이 사라지면 흐리게 표시한다. | `%APPDATA%\notch-cat\shelf.json` |
| 할 일 | 제목 + 알림 시각. 시각이 되면 노치가 내려와 알리고 "10분 뒤"를 고를 수 있다. 시각순으로 정렬. | `%APPDATA%\notch-cat\todo.json` |
| 한영 표시 | 앞 창의 입력기 상태(한/영)가 바뀌면 "가"·"A"를 1초 띄운다. Caps Lock도 같이 띄운다. | 없음 |
| 시세 | **기존 시세 위젯 설정을 그대로 읽는다**: `~/claude-memory/ticker/ticker_config.json`(종목 목록). 받는 방법은 `tools/ticker.pyw`와 같다(국내 6자리=네이버, 나머지=야후). 닫힘에선 한 종목씩 돌아가며, 펼치면 전체. | 읽기만 함 |

- ⛔ 총평가 금액은 넣지 않는다. 시세 위젯 규칙(`.claude/rules/widget.md`) — 금액은 코드가 있을 때만 보인다는 경계를 그대로 따른다.

## 5. 고양이
- 그림 원본: `desktop-cat/sprites/*.png`(117장). 바탕화면 고양이는 아직 영상 작업 중이라 그림이 계속 늘어난다.
- 상황 ↔ 그림 짝 목록 `notch-cat/cat_map.json` 하나로 정한다(예: 재생 중=`headphones`, 파일 놓음=`box`, 알림=`curious`/`headtilt`, 시세 오름=`happy`, 쉬는 중=그루밍 묶음). 코드를 고치지 않고 이 파일만 바꾸면 된다.
- 새 영상: `notch-cat/cat_video/`에 투명 영상(webm·mov)을 넣고 푸시하면, 빌드 워크플로가 ffmpeg로 그림 묶음(PNG 띠)으로 바꿔 exe에 넣는다. 사용자는 파일을 넣기만 한다.
- 그림은 노치 높이에 맞춰 줄이고, 바꿀 때는 살짝 겹쳐 사라지게 한다.

## 6. 생존 표시 (CLAUDE.md 0-1 규칙)
- 펼친 화면 구석에 "시세 09:41 · 가사 09:40"처럼 마지막으로 받은 시각을 둔다. 10분 넘게 못 받으면 그 글자를 경고색으로 바꾼다.
- 받기 실패는 `%APPDATA%\notch-cat\log.txt`에 남긴다(최근 500줄).

## 7. 빌드·배포 (`desktop-cat-exe.yml` 방식)
- `.github/workflows/notch-cat-exe.yml`: `notch-cat/**` 푸시 → windows 러너에서 `cargo test` → `cargo build --release` → **20초 실행 시험**(살아 있음, 창이 생김, 오류 로그 없음) → 통과하면 릴리스 `notch`에 올린다.
- 사용자에게 줄 받는 링크는 짧게(70자 안쪽). 파일 카드(SendUserFile)로 주지 않는다.
- 새 버전 확인은 알려주기만 한다. 스스로 바꿔 깔지 않는다(백신 오탐, 시세 위젯 2026-10-30 경험).
- 시작할 때 자동 실행은 설정에서 켠다(기본 켬, `HKCU\...\Run`).

## 8. 단계 (단계마다 exe를 받아 써 볼 수 있게)
1. 노치 틀: 창·합성·스프링 움직임·펼침/접힘·전체 화면 숨김 + 음악 + 가사
2. 파일 선반
3. 할 일 알림
4. 한영 표시 + 시세
5. 고양이 짝 목록 + 영상 자동 변환

## 9. 검증 — "됐다"는 증거로 말한다
- 단계마다: 실제로 곡을 틀고(유튜브·스포티파이 등) **노치에 보인 곡명·가사 줄 ↔ 재생기 화면**을 대조한 화면 사진.
- Nusa와 나란히 띄운 화면 사진, 펼침 움직임을 짧게 녹화해서 끊김을 본다.
- 메모리·CPU 수치(작업 관리자 값)를 Nusa와 함께 적는다.
- 순수 로직(LRC 해석, 스프링 계산, 할 일 시각 판정, 시세 응답 해석)은 `cargo test`로 한다.
- 확인 못 한 것은 "확인 못 함"이라고 먼저 말한다.
